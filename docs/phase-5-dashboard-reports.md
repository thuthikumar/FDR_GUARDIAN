# Phase 5: Dashboard, Search/Filtering, and Reporting Foundations

Phase 5 adds database-backed dashboard aggregates and read-only reports. The endpoints reuse the Phase 3 role matrix: `report.read` is required for dashboard and JSON report access; `report.export` is additionally required for CSV. Institution administrators are restricted to their own institution in every query, including aggregate and export queries. Other proposed roles remain system-wide as defined in the role matrix. This is an application permission proposal, not a verified AICTE role model.

All examples and seed rows are synthetic. The app does not access AICTE production data, services, or real FDR records.

## Endpoint table

| Method and route | Permission | Result |
| --- | --- | --- |
| `GET /api/v1/dashboard/summary` | `report.read` | Institution, FDR, maturity, existing-case, and existing-alert counts. |
| `GET /api/v1/dashboard/charts` | `report.read` | Record status, 12 month maturity, top institution, and case status series. |
| `GET /api/v1/reports/institution-summary` | `report.read` | Paginated institution totals, active count, principal sum, and nearest future maturity. |
| `GET /api/v1/reports/maturities` | `report.read` | Paginated maturity records with date range, bucket, and institution filters and a sort whitelist. |
| `GET /api/v1/reports/institution-summary?format=csv` | `report.read` + `report.export` | Full authorised institution summary CSV. |
| `GET /api/v1/reports/maturities?format=csv` | `report.read` + `report.export` | Full authorised maturity result CSV using the supplied filters. |

CSV columns are fixed and omit internal database IDs, scope IDs, and audit internals. Exports start with a UTF-8 BOM and two metadata rows (`Generated at`, `Data source: synthetic demo`). Values beginning with `=`, `+`, `-`, `@`, tab, or carriage return are prefixed with a single quote. Each CSV request writes one append-only audit event containing the actor, report name, selected filters, and row count; row contents are never copied to the audit event. JSON reports are read-only and do not create audit events.

## Metric definitions

- **Total institutions** counts institution rows. Institution administrators see their own institution only.
- **Total FDR records** counts records in the caller's scope.
- **Active records** counts scoped records whose `record_status` is exactly `active`.
- **Upcoming maturities** counts scoped records with `maturity_date` from the app's current date through 90 days ahead, inclusive, regardless of record status.
- **Overdue-date review** counts scoped records with a stored maturity date earlier than the app's current date. This describes a date in stored data; it does not establish invalidity or fraud.
- **Pending verification cases** counts existing scoped cases in submitted, under review, more information required, pending approval, or release pending states. It does not create or infer cases from FDR verification status.
- **Unresolved alerts / discrepancies** counts existing scoped alerts with status `open` or `acknowledged`. No alerts or discrepancies are generated by Phase 5.
- **Records by status** groups scoped FDR rows by `record_status`, including zeroes for declared statuses.
- **Maturities by month** groups scoped records from today through the following 12 calendar months; every displayed month is included, including zero-count months.
- **Institution distribution** groups scoped records by institution and returns the ten largest groups plus an `Others` count for the rest. Institution administrators see only their own group.
- **Cases by status** groups existing scoped verification-case rows by workflow status, including zeroes for declared statuses.
- **Institution summary** counts all associated FDRs, counts active FDRs, sums principal across those FDRs, and finds the earliest maturity date on or after today.
- **Maturity report** returns each matching record and a bucket computed from the date difference. Optional dates are inclusive. Sorting is restricted to maturity date, amount, institution name, and record status.

The current application date comes from `Asia/Kolkata`; date calculations accept an injected aware datetime for deterministic tests. Demo defaults are **urgent 0–7 days**, **attention 8–30 days**, **upcoming 31–90 days**, **normal over 90 days**, and **overdue-date review** for past dates. Environment variables `MATURITY_URGENT_DAYS` (7), `MATURITY_ATTENTION_DAYS` (30), and `MATURITY_UPCOMING_DAYS` (90) configure these cutoffs. These are demo defaults, not AICTE policy.

## Limitations and verification

Alert and discrepancy rows are only reported as they exist in the database; Phase 5 does not generate them. Verification backlog and discrepancy reports are out of scope until later phases. Pending verification metrics can therefore be zero until existing workflow data is populated. All monetary values are reported in the record's stored currency; current synthetic records use INR. Dashboard widgets show independent loading, empty, and error states. CSV downloads use authenticated API requests and are permission checked on the backend.

Run frontend checks from `frontend/` with `npm.cmd test` and `npm.cmd run build`. Run backend tests from `backend/` with `python -m pytest -q` and a dedicated reachable PostgreSQL test database as described in the README.
